# 中华文化书院 · 视觉方案「书院 · 檐棂印」设计说明

> 本文说明这套界面每一处为什么这样做。所有色值、体积、对比度均取自实现代码实测，不是估算。
> 对应稿件：`design/demo/v2/`（主页 / 登录页 / 资讯详情 / 靛青备选 / 已上传封面图对照）

---

## 一、要解决的问题

审看反馈是：现有界面**不是不好看，是看不出这是书院**——不够「书香门第」，一眼留不下印象。

诊断下来，缺的不是装饰，是**主体**。

参照物是故宫博物院小程序。它之所以让人一眼记住，并不在于多精致，而在于**它贴着自己的主体**：紫禁城的建筑、院藏的文物。换句话说，它的视觉就是它自己。

我们的主体是**「中华文化书院」**——一个概念，不是一处建筑。由此定下两条边界：

- **不照搬故宫。** 故宫的识别度来自它自己的藏品与宫殿，借过来只会得到一个"像博物馆的东西"。
- **不迁就校园实景。** 书院是虚拟概念，线下校区是现代建筑，硬去对应只会两头不着。

目标因此很明确：**让人一眼认出「这是书院」，并且耐看。**

## 二、方案：一幅画 + 三件记忆装置

### 卷首 · 青绿山水

审看时指出「特别对故宫博物院那种感觉情有独钟」。那种感觉的来源不是纹样，是**结构**：一张院藏的画通栏铺满、一直顶到状态栏后面，内容以一张纸的形式从下面浮上来压住画脚。这一条是可以学的，而且学的是做法不是画面。

画的内容学不来，但**画种**可以。青绿山水是石青、石绿两种矿物颜料画在绢上的，它有三条可以自己画：远淡近浓、山脊勾泥金、山与山之间留白。于是卷首是一幅我们自己生成的青绿山水——四层山脊，每层四件事：

| | 做法 | 为什么 |
|---|---|---|
| 山形 | 峰两侧各加一个「肩」，并随机带子峰 | 只有峰谷交替时曲线只能是正弦，出来是波不是山 |
| 设色 | **每一层自己也是渐变**：山头压到本层的石青，山脚退到下一层的浅色 | 平涂色块是矢量图，分染才是画 |
| 皴 | 近两层落披麻皴，从峰肩往下拖 | 皴是中国山水画和「色块山」唯一的区别 |
| 点景 | 中景一排米点树，近景两三丛松 | 米点是米芾的办法，这个尺寸下比画树形准确 |

泥金勾脊用 `--gold`，一层比一层粗一点点——这是画里区分远近的老办法。

### 四季

同一幅画换四套颜料：**春青绿 / 夏烟雨 / 秋浅绛 / 冬雪霁**。

画不用重画。山形、皴、点景、勾线全部走 `var()`，一个季节换的只是颜料——这正是青绿与浅绛在传统里的关系：**同一套笔墨，换一套矿物色**。落地时按服务端下发的 season 给 `.hero` 加一个类即可（`.hero--xia` / `.hero--qiu` / `.hero--dong`，春是默认）。

### 二级页用同一套卷首

资讯详情也是「一幅画顶到最上缘 + 檐叠在画上 + 纸从画脚浮起」，只是矮 100px（这一页的主角是正文），并且换了一幅画——同一支笔、不同一张画，比两页共用一张图更像书院自己的东西。

标题**不压在画上**，落到纸上第一行。理由和封面图是同一条：画是用户传的，标题的可读性不能交给它。

## 三、三件记忆装置

记忆点必须**少而重复**。堆十种纹样等于没有纹样。整套只立三件，外加几件配角。

### 装置一 · 檐

**为什么是檐。** 讲堂、山门、书院——中式建筑最先被认出来的永远是屋顶。更重要的是，它可以出现在**每一页的同一个位置**。重复即记忆。

**它是由构件拼起来的，不是一条装饰线。** 从上到下：

| 构件 | 作用 |
|------|------|
| 正脊 + 鸱吻 | 屋顶的顶，两端各一只吻 |
| 筒瓦 | 半圆截面的瓦垄，一根根排开 |
| 檐口金线 | 屋面与檐口的分界 |
| 瓦当 | 筒瓦的圆形收头 |
| 滴水 | 板瓦沟里的如意形垂片，与瓦当相间 |
| 檐檩 | 一根圆木梁，把椽头串起来 |
| 椽头 | 露在外面的木方端头 |

**起翘曲线用八次方。** 真屋檐正面看是「中间一条近乎平直的檐口，只在最外两端急促翘起」。二次、三次方会做成整幅下垂的弧——远看就是一块挂着的布。这一版曲线让中间 70% 几乎不动，翘全部集中在最外侧，才是翼角。

**二级页的檐矮一半。** 身份保留，版面不被吃掉。

**瓦是青灰的，不是木色的。** 屋顶本来就不是木头。给瓦自己的黛青色调之后，木构件（椽头、檐檩、枋、匾）才衬得出来，整页也不会一片棕。

### 装置二 · 棂

**用冰裂纹，不用步步锦。** 步步锦是规整的几何，画出来很容易被读成棋盘格或网格纸。冰裂是无规则的，一眼就是中式窗棂或瓷器开片，不会认错。

**它是结构，不是贴花。** 冰裂纹铺在功能入口区的「格心」里，而那一整块被做成一扇**槅扇门**：上下枋（木横档 + 金线）夹着格心，格心四角有角叶。装饰与结构合一，这一点是和市面上「在旁边贴一朵花纹」的中国风拉开距离的地方。

### 装置三 · 印

**朱砂取自校方印章本身。** 所以全站的按钮红、栏目印、选中态、标签，永远是同一个红——不会出现两种红打架。

**它是全站唯一的高饱和色，只出现在小面积。** 大面积永远是纸与墨。

**钤印不能是印得完美的。** 真印章有三个特征，缺一件就成了"贴了张图片"：

1. **歪一点点**——而且左右交替，两枚印不会歪成同一个角度
2. **边缘缺墨**——用噪声遮罩做出零星漏白
3. **深浅不匀**

## 四、配角装置

### 瓦当与小篆

五个功能入口装在同一枚**瓦当**里，当心是**小篆单字**：闻 / 览 / 讲 / 籍 / 集。

瓦当按**文字瓦当**的规制做：外缘、联珠纹、弦纹、界格。汉代瓦当分两路，一路用纹样（莲瓣、云纹）占满当面，一路是文字瓦当（「长乐未央」那种），中间是字、四周是界格——**两者不混**。既然当心要放字，就按文字瓦当来。

小篆字形由校方提供，取自《说文解字》小篆，是**玉箸**一路（笔画粗细均匀、体势端正对称），与这套细线几何完全合拍。

**当面做成金镶玉。** 玉不是均匀的半透明体——它有絮、有棉、有两处不在同一个地方的高光，这点不匀才是玉和塑料的分界，所以当面是：两道高光 + 一层低频的「玉花」噪声 + 一道从青白到豆青的四段径向渐变。外缘、联珠、弦纹、界格全部改成金，弦纹里侧留一道暗线当「坎」——金是**镶**上去的，不是画上去的。

字也跟着改：不再是阴刻的陶字，而是**嵌在玉里的金字**——字身走一道自上而下由亮金转暗金再回亮的渐变（金件的受光就是这样），字的上沿有一道暗坎、下沿有一道白反光，于是字是沉在玉面里的。

### 匾额

「精品好物」做成一方**浅木阴刻匾**。

这里改过一次。上一版是黑漆金字匾——规制没错（书院祠堂的匾本来就是这个），但整页转向清新典雅之后，它变成了第一屏唯一的深色块，自己成了那个「古板」的点。

换成浅木之后，金字失去对比，所以字也跟着换：**阴刻填墨**。这本来就是木匾的做法，描金是黑漆匾的做法，两者不混。字是墨色的，字的**下沿**有一条木本色的高光——那是刻槽的下壁在受光；少了这条高光，字就只是印上去的。

框与面分开两档：框是竖纹（框条竖着开料）、比面深两档；面是横纹（匾板是横着的一块整料）、微微凹进去。内框是一道刻出来的槽，金线躺在槽里。

### 冰裂棂

五个入口背后是一扇**冰裂纹窗棂**。棂条不是单线——每根是**四道叠起来的**：落影、暗边、条身、顶部高光。四道叠完，条子才是有厚度的木，而不是画在纸上的线。

### 装裱

所有会放封面图的位置，都按**装裱**来做：裱边、包角、压角印、题签。这一套的用意见第六节。

### 祥云

深色块底部压两层祥云，代替常见的波浪。波浪读起来是山水或海浪，都不是书院的词。

一朵祥云 = **一簇大小不一的圆瓣 + 云卷 + 沿上缘的内轮廓双钩**。连续均匀的圆弧带做出来是花边，不是云——真祥云是一团一团断开的，团里还有卷。

## 五、配色

全站颜色分七族，**每一处都从令牌取，不允许写死**。这条由构建期护栏 `check:design-tokens` 强制（首次跑出来抓到 43 处写死的棕色）。

### 纸

| 令牌 | 色值 | 用途 |
|------|------|------|
| `--paper` | `#F5F2E9` | 页面底：宣纸 |
| `--paper-card` | `#FCFAF4` | 卡片 |
| `--paper-sunk` | `#E9E5D9` | 凹陷 / 分隔 |
| `--paper-1/2/3` | `#F6F2E6` / `#EEE9DA` / `#E2DCC8` | 签条、印纸、内嵌 |

纸从 42° 的暖奶油挪到 45°、彩度只剩 5%，接近宣纸的白。整页「陈旧感」有一半来自这里。

### 青（天青 / 影青）

`--qing-05` `#F4F8F6` → `--qing-95` `#253230`，十一档。

汝窑天青、青白瓷的那一族，中国色里最典雅的一支，而且是**冷色**。

加它的理由是实测出来的，不是感觉：改版前有彩色像素的**色相中位数是 40°**，整页挤在暖黄区，**一个冷色都没有**。暖 + 深 = 陈旧；清新必须有冷色作对照。它同时接管了原先用墨铺的那些「图位」。

### 山（青绿山水的四层矿物色）

| 令牌 | 色值 | 位置 |
|------|------|------|
| `--shan-4` | `#D2E2DA` | 最远，近乎融进绢色 |
| `--shan-3` | `#A9C8B9` | |
| `--shan-2` | `#74A092` | 石绿 |
| `--shan-1` | `#467A86` | 最近，压到石青 |

远淡近浓——这是画种自带的规矩，不是我们定的。

### 木（`--wood-05` 至 `--wood-95`）

| 令牌 | 色值 | 色相 / 饱和 / 明度 |
|------|------|------|
| `--wood-20` | `#EADFCB` | 39° / 42% / 86% |
| `--wood-50`（主色） | `#B9A383` | **36° / 28% / 62%** |
| `--wood-70` | `#7F6E55` | 36° / 20% / 42% |

木头只做**框、线、小件**：裱边、枋、包角、椽头、匾、棂条。不铺大面。

### 墨（大面积深色）

`--mo-40` `#6E6A62` → `--mo-90` `#232120`。清新化之后墨只剩三处用途：正文与标题、阴刻填墨的匾字、需要绝对对比度的地方。

### 瓦 / 朱 / 金 / 石

| 令牌 | 色值 | 用途 |
|------|------|------|
| `--tile` | `#9FAEB2` | 黛瓦，193° 偏青；彩度只有 7% |
| `--zhu` | `#A8342A` | 朱砂，**全站唯一高饱和色**（彩度 49%） |
| `--gold` | `#C8A45C` | 细线、描边、泥金勾脊、金镶玉的镶 |
| `--shi` | `#C6D1D4` | 青白石：微信授权登录那颗按钮 |

### 三条关键的配色判断

**① 木色色相钉在 36–38°。**

咖啡与胡桃在 25° 上下、**偏红**——那是老家具的色相。金丝楠、白橡偏黄。这一条是「老气」与「上档次」的分水岭。

| | 色相 | 观感 |
|---|---|---|
| 最初的 `#6B4A32` | 25.3° | 咖啡 |
| 中途的 `#9A6E48` | 27.8° | 还是咖啡 |
| **现在的 `#B9A383`** | **36.0°** | 浅原木 |

**② 「老气」的配方是深 + 高饱和 + 偏红 + 铺大面，只调色相没有用。**

前两轮只在色相上挪（25°→27.8°→34.5°），明度、饱和度、面积一个没动，所以审看时连着说了三次「木色好像还是没什么变化」——他说得对。这一版四条同时改：明度提上去、饱和度压下来、深色面换掉、木头退回构件。

**③ 「古板」是可以量出来的，量完再改。**

审看时指出「显得有些古板，尤其是色调」。没有凭感觉改，先量了第一屏：**深色块占 36%、色相中位数 40°、冷色像素只占 1.9%**。三个数字指向同一件事——整页又深又暖又没有对照。改的就是这三条。

（顺带一条教训：判断冷暖不能用 HLS 的饱和度。纸色 `#F5F2E9` 在 HLS 里是 38% 饱和，看着像个高饱和色，其实彩度只有 5%。近白色会把 HLS 饱和度撑爆，得用彩度 `(max−min)/255`。）

### 展馆分类色

三个馆用**同一个明度层级**，只在色相上各偏一点：天青 / 苔绿 / 影青。原先那组蓝绿饱和度高出一大截，三张封面摆在一起像来自三个地方。

## 六、材质与光

### 一条总规矩

> **光从上方来。**
> 阴刻（凿进去）＝ 上沿暗、下沿亮。
> 阳刻（凸出来）＝ 上沿亮、下沿暗。

方向一旦反了，立刻就是「贴纸」。这一条是所有立体效果的总开关。

### 五种材质

| 材质 | 用在哪 | 做法 |
|------|--------|------|
| **纸** | 页面、卡片、签条、选中的输入框 | 纤维噪声 + 中亮四周暗的晕 |
| **墨漆** | 首图、匾额、登录页 | 漆面 + 竖纹 + 斜掠漆光 |
| **木** | 裱边、上下枋、包角、椽头 | 三层不同周期的木纹 |
| **石** | 次按钮 | 比纸纤维更高频的颗粒 |
| **陶** | 瓦当 | 径向渐变胎体 + 内高光 + 落影 |

**纹理全部是 CSS 渐变与内联 SVG 噪声，零位图。** 可换色、可主题化、不占包体积——这对小程序的 2MB 主包限制是硬要求。

木纹用**三层不同周期**（5 / 23 / 13）叠加，错开周期才不会看出规则条纹；大面积木面另配一组宽周期年轮再打散一次。

### 状态与反馈

- **输入框未选中** = 凿进漆面的凹槽：不透明底（页面纹理透不过来），内阴影在上沿，底沿一道极细金反光
- **输入框选中** = 整块翻成纸，描边转朱砂。在书院里"输入"就是在纸上写字，这个隐喻比加个蓝框贴切
- **主按钮** = 朱漆块：顶棱高光 + 底棱暗边 + 金圈 + **侧壁**。那道侧壁是"能按下去"的来源
- **次按钮** = 石青块，与页面、与主按钮都不是一种材质
- **按下** = 下沉 1–3px、侧壁收掉。瓦当按下是下沉 + 朱砂一闪，像落了个印

幅度一律很小（1px / 0.6%）——大了就成弹簧。

### 毛边

**只给「一张纸」用**：题签、钤印那方纸。界面里的卡片是印刷品，边就该是齐的。抖幅只有一两个百分点，毛边是纸纤维的断口，不是撕破的口子。

## 七、封面图上传后，设计会不会被盖住

这是最实际的一个问题，答案是**部分会，而且是设计好的**。

| | 结果 |
|---|---|
| **会被盖住** | 画心里的祥云、木纹底——它们本来就在「图的位置」上 |
| **盖不住** | 裱边木纹 · 四角包角 · 右下压角印 · 竖排题签 · 标题绢条 · 题签签条 |

做法是把纹样**一律挪到画心之外，或压在画心之上**：

- **裱边**：木框，永远露在外面
- **包角**：装裱护角，只吃四个角，主体内容一点不挡
- **压角印**：中国画的画心右下角本来就钤印。**它本来就该压在图上**，不存在被覆盖的问题，占地极小却是最强的身份标记
- **题签**：名字写在签条上，图再满也盖不住
- **绢条**：标题落在一条半透明的绢上，同时保证任何照片上文字都读得清

换句话说：**以后每张封面图都会自动带上包角和一枚朱印，看起来就是一张裱好的画。**

对照稿见 `home-cover.html`。

## 八、字

### 正文与标题：内嵌宋体子集

- 字体：**思源宋体 Noto Serif SC**，SIL OFL 1.1，可商用、可嵌入、可子集化
- 子集：**4009 字符**（GB2312 一级 3755 + 项目全语料 + 书法繁体雅字 + 标点），单字重 400
- 体积：woff2 **689 KB** → base64 **919 KB**
- **主包 1530 KB / 2048 KB，余量 518 KB**

**为什么内嵌而不用 `wx.loadFontFace`：** 后者只收网络地址，要配 `downloadFile` 合法域名，还必须返回 `Access-Control-Allow-Origin: *`（设成 `servicewechat.com` 时 iOS 能过、安卓挂），荣耀 / vivo 等机型对字体 CORS 的校验更严——**做不到「所有设备都正常显示」**。内嵌进代码包则不走网络、不需要白名单、没有机型分裂。

`font-family` 回退栈保持完整：字体万一没生效就退回系统字，**不会白屏、不会豆腐块**。

### 入口：小篆字形

校方提供的《说文》小篆 SVG。清洗做了两件事：

1. **剔除水印**——原始文件每个字都夹着两条近白色路径，白底上看不见，落到纸色或深色底上会显形
2. **归一化**——字面统一到 1000×1000、居中占 760，五个字的高度与线宽这才一致

## 十、工程护栏

设计要能长期不走样，靠的不是自觉，是护栏。两条已挂进 `preflight:local`：

**`check:design-tokens`** —— token 定义区之外不允许出现写死的木色/纸色。
这条不是预防性的：第一次运行就审计出 **43 处**写死的暖棕，首图、匾额、展馆封面、登录页这些大面积的颜色全都没走变量——这正是前两轮「改了木色却看不出变化」的原因。人眼查不出来，只能靠机器。

**`check:font-subset`** —— 管三件事：字体产物与源文件一致、所有写死的中文都在子集内、主包体积留有余量。三条都做过变异验证。

## 十二、和微信原生控件的关系

右上角那枚胶囊（··· ○）位置固定、不能移动也不能隐藏，而且永远画在页面内容之上。
375pt / statusBarHeight=44 的机型上它占 y 48–80、x 281–368，**正好落在屋檐的瓦面上**。

定的规矩，按优先级从高到低：

1. **版面优先。** 不为让开原生控件去动整页布局。
   试过在状态栏和屋檐之间留 40px 让胶囊坐在"天"上、屋檐完整——
   代价是登录页少 40px、底部被挤塌，只能到处收间距。本末倒置，撤了。
2. **按钮之间不许重叠。** 这一条不能让。已实测：三页里所有可点元素
   （工具位、搜索、返回、按钮、标签栏、入口、题签）与胶囊矩形**零重叠**。
3. **不许挡文字。**
4. 有条件就避开设计元素；避不开，压在纹样上但不挡字是可以接受的。
   胶囊压在瓦面上不影响任何操作，那就让它压。

登录页的返回键据此挂在**檐下**，不去和胶囊抢同一条水平线——
和胶囊对齐成一条导航栏确实好看，但那要求屋檐先让位，为一枚按钮动整页不划算。

`.cap-zone` 这个元素保留（高度 0），它是唯一的调节点：
真机上万一某个机型的胶囊位置特殊、压到了要紧的东西，
把它的高度改成 `wx.getMenuButtonBoundingClientRect()` 算出的 navContentHeight 即可
（`miniapp/utils/navbar.js` 里已有这个函数）。

**还需要真机确认的一条**：胶囊图标的黑白由 `navigationBarTextStyle` 决定。
我们顶部是浅色，应该用 `black`；但二级页上传深色封面图后顶部变深，需要切到 `white`。
`wx.setNavigationBarColor` 在 custom 模式下部分机型不生效，这一条我无法在稿上验证。

## 十三、图片框的四角：如意云头角叶

所有"放图片 / 放画"的地方共用同一件铜活，一共三处尺寸档（只改 `--bj` 一个值）：

| 档 | 用在哪 | `--bj` |
|----|--------|-------|
| 大 | 卷首画心 `.mount--lg`（333×176） | 32px |
| 中 | 展馆封面 `.mount`（125×92）22px、二级页配图 `.fig-box`（335×156）28px | 22 / 28px |
| 小 | 资讯缩略图 `.mount--sm`（77×55） | 14px |

**改过三版，前两版都是被看出来的，记在这里免得再犯。**

**一版**是一块**实心斜三角**加一条亮边。当时的原话是「像创可贴」——很准：
平涂、没有厚度、没有投影，颜色又和裱边的木色撞在一起，就是一块贴上去的胶布。

**二版**改成折绢：加了明暗、金线、投影。质感上去了，但**形状还是实心三角**，
于是在 125×92 的展馆卡上出了更大的问题——四个角一切，矩形成了八边形，
审看时问「这照片位是不是在模仿中式园林的窗户？形状不对」。
不是窗，是包角画大了：30px 的角占 92px 短边的 33%，两个角一接头，短边就没了。

**三版**把它改成 L 形金条，形状对了（矩形还是矩形），但两条臂是**分开画的**：
肘部有接缝和一级台阶，末端是齐口切断。反馈圈出肘部说
「真的感觉怪怪的，而且也没能体现中华传统元素」——两句都对。
那只是一个 L，它不是任何一件东西。

**四版（现在这版）回到器物本身。** 明式家具上包在箱匣、柜门四角的那件铜活叫**角叶**。
明式铜活的路子是「造型简练、以线为主」：角叶贴着两条边走，
外沿与板面齐平（所以外沿是直的），**所有的形都做在内沿**，收头取如意云头，
肘部钉泡钉。纹样母题上，如意、云头、四合如意正是明清家具最常用的一组。

具体到这一件：

- **一条闭合路径画完整件 L**，肘部没有接缝，也就不会再有台阶；
- 外沿两条直线贴着画心的边，内沿是一条连续的曲线；
- **两端各收一个如意云头**：先鼓出一瓣，再回卷成云尾尖收在外沿上，末端不再是齐口切断；
- **肘部是四合如意式的双卷云头**，向对角外凸，在对角线上留一个尖，是整件的视觉中心；
- **肘部与两臂各一枚泡钉**——明式铜活一定有钉，它是钉上去的，不是画上去的；
- 断面走渐变：外沿高光 → 金亮面 → 金中面 → 内沿暗边。两条臂各用一条垂直于自己的渐变，
  沿对角线分界；对角线上两条渐变取值相同，所以没有接缝；
- 底下垫一层虚化的投影，让它浮在画心上。

**四个角是四张单独生成的图，不是同一张翻转。** 翻转会把投影方向也翻过去，
而光是从左上来的，投影必须永远朝右下。四个角的明度也不同：左上最亮，右下最暗。

图形由 `_ornaments.py` 的 `jiaoye()` 生成，落成 `--jiaoye-tl/tr/bl/br` 四个令牌
（data URI），CSS 里就是四层背景。相比二版的十六层渐变，反而更轻。

三道护栏，都做过变异验证：

- **`_assert_jiaoye_sound()`**（生成器内）：四个角齐、轮廓关于对角线严格对称
  （不对称两条臂就不一样长）、四个角的投影一律朝右下。
- **`check:corner-brackets`**（`preflight:local`）在真浏览器里量：
  边长 ≤ 短边 1/3（八边形那条线）、正好四层背景且都是 data URI、
  以及**四个角的图互不相同**——最后这条防的是「四张图其实是同一张」，
  同类 bug 在标志 A/B 对照那一轮真的发生过。

## 十四、屋檐的颜色：统一

登录页原来单独覆写了 `--tile-*`，屋顶比其它页偏一档。现在撤销了覆写，
**三页共用同一套黛青瓦**（`--tile #6E93A3` / `--tile-2 #8AACBA` / `--tile-dark #456A7B` / `--tile-hi #ACC7D3`），
已逐页量过计算值，三页完全一致。

选统一而不是保留差异，理由是：屋檐在这套设计里是**页头的身份**，
不是某一页的装饰。它每页都在同一个位置、同一个高度，颜色一变就会让人以为换了产品。
登录页要和别的页不一样，靠的是画面里没有内容卡、靠居中的标志和那块匾——
不需要再靠换屋顶的颜色。
