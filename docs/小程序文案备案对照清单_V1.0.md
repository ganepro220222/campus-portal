## 9. UI 视觉补充轮（V1.1）

V1.0 只动了字符串，声明「不涉及 UI 视觉」。落地后复查发现有四处**属于视觉呈现层面**的问题：
两处是 V1.0 改文案带出来的（改了预览没改成品、改了措辞留下电商暗示），
两处是 V1.0 范围之外、但审核员必看的界面缺口（AI 生成标识、协议页空白）。本轮一并处理。

### 9.1 AI 生成内容标识（新增 · 优先级最高）

《生成式人工智能服务管理暂行办法》第十二条与《互联网信息服务深度合成管理规定》要求在**界面显著位置**标识生成内容；
微信小程序对 AI 问答类功能按同口径审核。原「智能问答」页与「书院助手」浮标抽屉**均无任何标识**。

| 文件 | 变更 |
|------|------|
| `packageD/ai-chat/index.wxml` / `.wxss` | 输入行外包 `.chat-foot`，其下常驻 `.ai-note`「内容由 AI 生成，仅供参考」 |
| `components/ai-assistant/index.wxml` / `.wxss` | 抽屉输入行外包 `.sheet-foot`，同一条标识 |

实现要点：分隔线与 `env(safe-area-inset-bottom)` 从输入行**上移到外层容器**，
标识落在安全区之上而不是被 Home Indicator 压住；两处均 20rpx / `--muted`，
沿用业界（豆包 / 元宝一类）输入框下方常驻灰字的写法。底栏增高 ≈14–34rpx，
由 `flex:1` 的消息区吸收，不改变任何既有间距。

### 9.2 分享海报：预览与成品不一致

V1.0 把**预览**底部 `pf-2` 改成「扫码进入云端书院」，但 `_render()` 里 Canvas 实际绘制的底栏
仍是「长按识别小程序码 · 云端书院」（V1.0 §3.8 标注为保留不变）。海报是保存到相册、
转发到微信的**对外物料**，"所见即所得"被打破；且同一张图上「扫码」与「长按识别」互相矛盾——
图片在微信里的正确识别方式是长按。

### 12.1 首页入口卡是全场唯一贴边的卡片（存量问题，本轮一并修）

元素写的是 `class="entries-wrap wrap"`，本意是套用 `.wrap` 的 `padding: 0 32rpx` 缩进。
但 `.entries-wrap` 在文件里排在 `.wrap` 之后、specificity 又相同，它自己的
`padding: 30rpx 12rpx 24rpx` 把横向缩进**整个盖掉**了。

逐个核对了页面里所有带 `wrap` 的元素：

| 元素 | 是否自带 padding | 结果 |
|------|------------------|------|
| `.wrap`（轮播） | 否 | 缩进 32rpx |
| `.craft-banner wrap` | 否 | 缩进 32rpx |
| `.section wrap` | 否 | 缩进 32rpx |
| **`.entries-wrap wrap`** | **是** | **贴屏幕边，0 缩进** |

也就是说这张带 1rpx 描边、28rpx 圆角和投影的白卡，是首页唯一一个左右贴边跑的——
两侧圆角和阴影全被压在屏幕边缘上。缩进改用 `margin: 24rpx 32rpx 0` 表达，不再和 padding 打架。

> 这一处是存量问题、不是 B2 引入的，但它改变了首页可见布局。若你们本来就想要贴边效果，
> 回退这一条即可，其余四处互不影响。

`.entry { flex: 1 }` 均分 + `.ico` 死宽 100rpx + `.entry-label` 是 `nowrap` 且无省略号。

| 条数 | 改前每格宽 | 结果 |
|---|---|---|
| 5 | 134rpx | ✓ |
| 6 | 111.7rpx | 勉强 |
| 7 | 95.7rpx | ✗ 图标 100rpx 顶出格子 |
| 8 | 83.8rpx | ✗ 同上 |

文案同理：5 字以上（115rpx）在 6 条时就会和邻格叠在一起。

第 6 条起自然落到第二行，每格恒为 132.4rpx；标签加 `max-width:100%` + 省略号。

## 15. 公司主体备案路径下的复审（V1.7）

### 15.1 先纠正一个认知：Mock 数据不影响审核，兜底 DEFAULT 才影响

### 16.3 篆印替换带出来的三个坑

换素材不是改个路径就完事，校徽是 1:1、篆印是 560×499（1.122）：

1. **配色要分背景**。渲染对比后确认：金印落深蓝（登录页/关于页）清亮，
   而**金印落白底整个发灰**；海报有「鎏金」模板，金印在金底上几乎不可见。
   故深色背景用金印并**去掉白底圆**，白底圆（海报预览与画布）用深蓝印。
   顺带去掉登录页那条 `0 20rpx 56rpx` 向下投影——没有实体白盘再投影，
   只会在深蓝上糊出一块脏暗圆。
2. **画布会把印面压扁**。`ctx.drawImage(badge, x, y, box, box)` 硬画正方形，
   1:1 的校徽看不出问题，1.122 的篆印会明显变形。抽出 `badgeFitRect` 按图片
   **真实比例**做 aspectFit（不硬编码 1.122，换素材不用回来改），补单测并反向验证。
3. **六处容器尺寸都要重算**。海报预览 `.p-seal-img` 118 正方经 aspectFit 后对角
   158rpx，比 150rpx 的圆还大，四角会露到圆外；画布侧有 `ctx.clip()`，
   同样超框会被裁成缺角。统一到 **0.61 占比**（方形内接圆的临界是 0.747），
   预览与成品一致。

顺带修一个真 bug：关于页 `icp` 兜底是空串、`wx:if` 恒假，**这行从未渲染过**——
备案号在小程序里根本看不见，而这是《互联网信息服务管理办法》要求展示的。
拉取逻辑还写着 `icp: res.icp || ''`（其余字段都是 `|| this.data.xxx`），
后台一旦返回但没带 icp，兜底值会被抹成空。两处一并改掉。

包体积：移除已无引用的 `school-badge.png` 与 `school-title.png`，新增两枚篆印 68KB，
**主包净减 242KB**。

## 18. 实机截图带出的三处修复（V1.10）

### 18.1 个人中心仍显示学校名 —— 兜底改了但没用上

`{{userInfo.college || '中华文化书院'}}` **只在字段为空时才兜底**。而 `profile.college`
是后端返回的真实值，历史数据里存的就是「贵州交通职业大学 · 中华文化书院」这串
界面占位文案——有值就原样显示，所以主体归属改完后个人中心照旧打着学校的名号。

改为按占位串名单归一化（复用 §16.2 建的 `PLACEHOLDER_COLLEGES`）：真实学院名照显，
占位串（含改文案前的旧串）一律显示「中华文化书院」。**不指望回头去洗历史数据。**

### 18.2 海报封面加载失败：预览留空白框，成品却是徽记布局

画布侧 `coverImg.onerror` 早就会降级成「居中徽记」布局，而预览侧只看 URL 合不合法、
不看图片是否真的加载得出来——于是预览是一个空白灰框、存下来的图却是徽记布局。
又一次「预览 ≠ 成品」。给 `.p-cover-img` 加 `binderror`，失败时把 `hasCover` 置 false，
两侧行为对齐。

### 18.3 登录页留白过大 —— 根因不是缺装饰

`.login-form` 是 `margin-top: auto`，**剩余空间全堆在品牌区与表单之间**；印章由
300rpx 收到 248rpx 后，多出来的 52rpx 又全落进那一块，于是显得空。

渲染比对了四种处理（现状 / 空白上下均分 / 放大印章到 272 / 加一道装饰细纹），
结论是**空间再分配**而不是填东西：
- 加细纹与上方既有的 ❖ 分隔纹重复，画蛇添足；
- 印章放大到 272rpx 会压住「云端书院」标题，呼吸感变差。

做法：`.seal` 的 `margin-top` 由 48rpx 改为 `auto`，与 `.login-form` 的 auto 配对，
剩余空间上下均分；48rpx 并进 `.login-inner` 的 `padding-top`（60 → 108rpx）作为保底，
**空间不足时印章距顶与改前逐像素一致**（108+statusBar ≡ 60+statusBar+48），
小屏退回紧凑布局，不会贴住状态栏。

各机型分配（rpx）：iPhone 8 剩余为负 → 两处 auto 归零；iPhone 13 上下各 +54；
15 Pro Max 上下各 +142。

### 18.4 活动列表页顶部标题截断 —— 未修，需真机复验

`pages/activity/index.json` 只有 `navigationBarTitleText`，用的是**微信原生导航栏**；
而截图里正常的个人中心、生成海报都是 `navigationStyle: custom` 自绘的。
原生导航栏由微信绘制，页面 CSS 影响不到它，**代码侧找不到能造成截断的因素**。

建议：真机复验一次。若真机正常，是开发者工具模拟器的渲染问题；若真机也截断，
可把该页改成与站内其他二级页一致的自绘 `nav-bar` 绕开。

> 另记一处产品命名：这是活动**列表**页，标题却是「活动报名」，用户可能以为已进入
> 报名流程。与首页入口「报名」是一致的，故未擅自改，供你们决定。

## 20. 导航栏方案统一（V1.11）

§18.4 当时的结论是「原生导航栏，页面 CSS 干预不了，建议真机复验」。真机确认后本轮做了迁移。

### 20.1 机理更正

原生导航栏并不会无条件裁切标题——若如此，所有小程序都会出这个问题。
真正的触发条件是**微信的字体大小设置**（我 → 设置 → 通用 → 字体大小）：
原生导航栏标题字号跟随该设置缩放，而栏高固定，调大后下缘就会被切。
自绘 `nav-bar` 走 rpx，不受该设置影响——这也解释了为什么只有这一类页面出问题。

顺带更正一处事实：仓库里用原生导航的**不止一页**，共 5 页
（`pages/activity/index`、`packageA/news/list`、`packageA/hall/detail`、
`packageB/course/player`、`packageC/college/webview`）。

### 20.2 迁移范围

| 页面 | 处理 | 说明 |
|------|------|------|
| `pages/activity/index` | ✅ 改自绘 | 与 `packageC/activity/detail` 同一流程，页面结构（`min-height:100vh`）完全一致 |
| `packageA/news/list` | ✅ 改自绘 | 同上 |
| `packageA/hall/detail` | ✅ 改自绘 | `height:100vh` + `flex:1` 滚动区，与 craft/resource/college 三个列表页同型 |
| `packageB/course/player` | ❌ 保留原生 | `<video>` 是原生组件且要全屏，固定顶栏会和它抢层级 |
| `packageC/college/webview` | ❌ 保留原生 | 根节点是 `<web-view>`，原生组件层级永远压在自绘顶栏之上 |

### 20.3 新增关卡

`scripts/check-wxml.js` 加检查 E：逐页比对 json 的 `navigationStyle` 与 wxml 是否画了顶栏。
用原生导航的页面必须写进 `NATIVE_NAV_ALLOWED` 并注明原因，否则报错。
反向验证过：把 `pages/activity/index.json` 改回原生，关卡立刻拦下。

## 21. 登录页留白再调（V1.11）

§18.5 用两个 `margin-top: auto` 把剩余空间对半分。反馈是「不太明显」——复核属实：
`auto` 只会**均分**，中间那段仍有 70~130rpx（随屏高涨），整屏仍被切成上下两半。

改成三根弹性隔条按 **3 : 1 : 3** 分配（印章上方 / 品牌与表单之间 / 表单与页脚之间）：
中间只拿七分之一，其余落到顶部光晕与底部波浪上，那两处本就是留白区。
`.foot` 同时从 `.login-form` 内部移出，成为 `.login-inner` 的直接子元素——
不然它上面那根隔条不参与 flex 分配。

浏览器实测（三档屏，与真实 WXSS 值一一对应）：

| 屏 | 印章距顶 | 品牌→表单 | 表单→页脚 |
|----|----------|-----------|-----------|
| SE 320×568 | 155 → 155 | 44 → 44 | 40 → 40 |
| iPhone 8 375×667 | 148 → 148 | 44 → 44 | 40 → 40 |
| iPhone 13 390×844 | 244 → 237 | **89 → 57** | 40 → 79 |

小屏隔条全部塌成 0，逐像素与改前一致，零风险；高屏上圈出来的那块空白收窄约 36%。
用户真机的可用空间比模型更大，收窄幅度还会更明显。

装饰仍然没加，理由同 §18.5：页面下方已有一组 ❖ 分隔符，再加一组是重复。
另有一条硬约束——iPhone 8 及以下整页已经**正好填满**，添加任何元素都会把小屏推进滚动。

## 22. 助手浮层遮挡、海报分隔符、后台内部措辞（V1.12）

### 22.1 书院助手抽屉被 tabBar 切掉底部 ⚠️ 视觉 bug

真机截图里，在带底部导航的页面打开书院助手，输入框与发送键整条被导航栏压住。

原因不是 z-index 写小了：抽屉是 `z-index: 610`，tabbar 是 `500`，数值上抽屉更高。
但**自定义 tabBar 由微信在页面之外单独渲染**，它和页面内容不在同一个层叠上下文里，
页面里给再高的 z-index 也盖不住它。所以只能让路，不能压过去。

改法：抽屉在 tabBar 页面上整体抬高 `108rpx + 安全区`（`.sheet.above-tabbar`）。
组件本身不知道自己被放在哪一页，`attached` 时用 `getCurrentPages()` 的 route
比对 tab 路由清单来判断。

顺带修掉一个会多让一截的坑：抬高后安全区那段已经由 tabbar 自己的 `padding-bottom` 占掉，
`.sheet-foot` 里就不能再算一次 `env(safe-area-inset-bottom)`。

**新增关卡 `check:tabbar-routes`**：tab 页清单同时写在三处
（`app.json` 的 `tabBar.list`、`custom-tab-bar/index.js` 的 `data.list`、
新增的 `utils/tabRoutes.js`），任一处改漏，浮层让位就会算错。
关卡把三份比一遍，并核对让位高度与 `.tabbar` 的实际高度一致。
反向验证过：删掉清单里一条、或把让位高度从 108 改成 100，都会被拦下。

### 22.2 哪些页面需要书院助手

改前是 7 处，且规律说不通：四个 Tab 里只有「首页」「动态」有浮标，
「展馆」「课程」没有，看着像漏做；课程详情页和播放页各有一个，是重复入口。

定下的规则：**Tab 层只在首页留一个总入口；内容详情页各留一个；列表页与播放页不留。**

| 页面 | 结论 | 理由 |
|------|------|------|
| `pages/index/index` | ✅ 保留 | 总入口 |
| `packageA/news/detail` | ✅ 保留 | 有具体内容可问 |
| `packageA/hall/detail` | ✅ 保留 | 同上 |
| `packageA/craft/detail` | ✅ 保留 | 同上 |
| `packageB/course/detail` | ✅ 保留 | 同上 |
| `pages/news/index` | ❌ 移除 | 列表页没有上下文；且四个 Tab 只有它有，规律说不通 |
| `packageB/course/player` | ❌ 移除 | 与课程详情页重复；播放场景不该再飘一个球 |

另有一层考虑：AI 是这次提审的风险点，入口越少越聚焦，
「在内容页可就当前内容提问」也比满屏飘球更好解释。这两处是各一行的改动，要恢复很容易。

### 22.3 海报分隔符

旧版是**一条通长实线 + 一个绝对定位压在正中间的 ❖**，两者直接重叠成一团
（预览与画布两边写法一致，所以「预览即成品」是成立的，只是一起难看）。

改成登录页 `.brand-div` 那套：两段线各自朝外淡出，中间给菱形让出空隙。
尺寸按海报宽 480rpx ÷ 登录页 750rpx = 0.64 等比缩下来（线 92→58、间距 20→14），
字号取 18rpx —— 等比算出来是 14rpx，在海报尺度上几乎看不见。
合计 162rpx，与旧版 160rpx 的占位基本一致，不影响上下留白。

画布侧按同一比例换算（海报 480rpx 对应画布 300px，系数 0.625）：
半宽 50px、❖ 半宽 5.5px、间距 9px，两段各用一个 `createLinearGradient` 做淡出。
已在真实 Canvas 2D 上渲染核对，预览与画布逐项对齐。

### 22.4 后台里写给自己人看的话

对着甲方的界面上出现了合同术语、内部排期和命令行指引：

| 位置 | 旧文案 | 问题 |
|------|--------|------|
| 首页轮播 | 「……（**验收标准**：5 分钟内同步）」 | 验收是我们和甲方之间的约定，不是给使用者看的 |
| 操作日志 | 「……满足**验收**「操作有日志」」 | 同上 |
| 展馆编辑 | 「……（**验收 §2.4**）」 | 内部文档章节号 |

| 意见反馈 | 「……（用户端消息通知**二期**接入）」 | 排期术语 |
| 登录页 | 「**开发环境**默认账号 admin / Admin@123 / **生产环境**请使用独立超管账号……」 | 已是 `v-if="isDev"`，打包发布时整行不存在；但第二句属于运维文档，不该印在登录页 |

- **关联小程序**：原文让后台使用者自己去跑 `node scripts/sync-navigate-appids.js`。
  改为「目标 AppID 需先加入跳转白名单才能打开，新增请联系技术人员配置」——
  这才是后台使用者该知道的边界。「接口同步」选项同时置灰（`disabled`），
  因为它尚未真正可用，选了会静默失效。
- **意见反馈**：查证后确认 `AdminFeedbackService#reply` 只把回复存进库，
  既不建消息也不推送，小程序端**没有任何地方能看到回复**。
  所以文案不是把「二期」删掉了事，而是如实写成
  「回复内容仅保存在后台备查，用户端不会收到通知；需要答复用户时，请使用其填写的联系方式」。

还有一处更严重的：`CollegeAppService#contentTypeLabel` 里 `api_sync` 的标签是
「接口同步（**预留**）」，而这个字符串**会随接口下发到小程序**，
显示在「关联小程序」条目上——内部路线图措辞一路漏到了审核员眼前。已去掉。

**新增关卡 `check:ui-copy`**：扫 `admin/src` 的 `.vue` `<template>` 与 `miniapp` 的
`.wxml`，只看会渲染出来的文本节点和 label / placeholder 一类属性（注释先剔除），

待实现 / 需求文档 / 技术方案 / 联调 / 压测 / 占位符 / TODO / FIXME / mock」即报错。
